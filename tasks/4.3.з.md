# Задание 4.3.з

Составьте SQL-запрос:

> исследуйте нештатные ситуации с объединением таблиц и сделайте соответствующие
> выводы:
>
> - объединяются таблицы различной арности;
> - в объединяемых таблицах соответствующие столбцы имеют различные типы данных;
> - на столбец одной из объединяемых таблиц наложено ограничение целостности
>   Primary Key, а соответствующий столбец второй таблицы имеет тот же тип
>   данных, но первичным ключом не объявлен.

---

## 1. Объединение таблиц различной арности

Таблицы `Клиенты` и `Поставщики` имеют разное число столбцов.

### Неправильно

```sql
SELECT * FROM Клиенты
UNION
SELECT * FROM Поставщики;
```

**Результат**: ошибка, поскольку количество столбцов в выборках различается.

### Правильно

```sql
SELECT Код_Клиента AS Код,
       Клиент AS Наименование
FROM Клиенты

UNION

SELECT Код_Поставщика,
       Поставщик
FROM Поставщики;
```

**Вывод**: для `UNION` количество столбцов в обеих выборках должно совпадать.

---

## 2. Соответствующие столбцы имеют различные типы данных

Можно объединить числовой код клиента и текстовое название клиента:

```sql
SELECT Код_Клиента
FROM Клиенты

UNION

SELECT Клиент
FROM Клиенты;
```

В SQL Server возникнет ошибка преобразования типов.

Корректный вариант:

```sql
SELECT CAST(Код_Клиента AS VARCHAR(20))
FROM Клиенты

UNION

SELECT Клиент
FROM Клиенты;
```

**Вывод**: соответствующие столбцы должны иметь совместимые типы данных либо
быть явно приведены к общему типу.

---

## 3. Один столбец является Primary Key, другой - нет

- `Клиенты.Код_Клиента` - первичный ключ;
- `Заказы.Код_Клиента` - внешний ключ, допускающий повторения.

Запрос:

```sql
SELECT Код_Клиента
FROM Клиенты

UNION

SELECT Код_Клиента
FROM Заказы;
```

Результат содержит уникальные значения кодов клиентов.

Для сравнения:

```sql
SELECT Код_Клиента
FROM Клиенты

UNION ALL

SELECT Код_Клиента
FROM Заказы;
```

Результат содержит повторяющиеся значения из таблицы `Заказы`.

**Вывод**: Наличие ограничения `PRIMARY KEY` в одной из таблиц не влияет на
возможность объединения. Важны только совместимость типов и количество столбцов.
Разница между `UNION` и `UNION ALL` заключается в удалении или сохранении
дубликатов.
